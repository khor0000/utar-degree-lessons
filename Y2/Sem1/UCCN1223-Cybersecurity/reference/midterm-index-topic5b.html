1. Concepts: what it means and where it is

ConceptOne-line plain meaningSlide no(s)
Network threats
Three network lossesLoss of confidentiality = wiretapping or eavesdropping. Loss of integrity = data corruption. Loss of availability = denial of service.4
Four potential harmsInterception, Modification, Fabrication, Interruption.5
InterceptionUnauthorised viewing of data. Also called eavesdropping or wiretapping.5
ModificationUnauthorised change to data. An integrity failure.5, 14
FabricationUnauthorised creation of new data. An integrity failure.5
InterruptionStopping authorised access to a service. Same idea as denial of service.5, 23
Interception vulnerability factorsSix reasons a network is easy to intercept: anonymity, many points of attack, sharing, system complexity, unknown perimeter, unknown path. Each has its own slide.6
AnonymityAttacker can strike from far away and hide the origin by passing through other hosts.7
Many points of attackData passes through many hosts. You depend on every host's access control, not only your own.8
SharingShared resources open access to more users than a single computer has.9
System complexityMixed operating systems are harder to secure. The attacker can make your computer do part of the attack's work.10
Unknown perimeterNetwork boundary is unclear. One host may sit on two networks with different rules.11, 12
Unknown pathMessages may be routed through hosts you do not control, and users seldom control routing.13
InsertionCrafting new data and adding it to a stream. The attacker need not break the encryption.14, 20
ReplayReusing a genuine, intercepted message, usually unchanged. Example: a dishonest merchant resubmits a transfer.14, 21
SequencingPackets arrive in the wrong order. Happens naturally when routes change. TCP keeps the order right.17, 18
SubstitutionSwapping one piece of a data stream for another, for example splicing two messages together.19
Physical replayListed on slide 16 and 22, but slide 22 has no text in the file. Check the printed slide.16, 22
Routing attackBad routing information spreads between routers and disrupts many paths. Routing is self-healing, but slowly.24, 25
Excessive demandOverloading a link, router or web server beyond its finite capacity.24, 26
Component failureHardware breaks irregularly. Non-malicious, so seldom caused by an attack.27
Port scanningInspection that does no harm itself, but is often the first step of an attack.28
Wireless security
Wireless exposureWireless signals can be received by anyone with an antenna in range. Traffic must be protected between computer and access point.30
Wireless vulnerabilitiesGrouped as confidentiality, integrity and availability. Example: forged data (integrity), interference (availability).32
WEPWired Equivalent Privacy. Early Wi-Fi encryption from the 1997 802.11 standard. Very weak; cracked in minutes.34, 35
WEP weaknessesThree groups: short 24-bit initialisation vector (IV) that repeats, one static key shared for a long time, and a weak encryption process.36, 37
WEP key handlingNo automatic key distribution or rotation. Admins change keys by hand, and organisations often keep one key for years.37
WPAImproved over WEP. Uses TKIP, which changes the key automatically for each packet. Rated weak in the comparison table.38, 39
WPA2Adds AES encryption (RC4 still supported for compatibility). Rated secure.38, 39
WPA3Uses AES. Strongest, resists brute-force attacks. Rated very secure.39
Rogue access pointUnauthorised wireless access point connected to a network without the administrator's approval. Bypasses firewall and other controls.45, 46
Man-in-the-middle (wireless)Attacker spoofs the access point's MAC address, then sends the device a disassociate request (ARP spoofing).41, 42
Denial of service (DoS)
DoSAn attempt to defeat availability so a user is denied authorised services or data. The deck describes it as a single request to a server.43
How DoS blocks accessThree ways: crash the application with a software vulnerability; interfere with routing; manipulate access-control data (delete permissions or disable the control).44
Distributed denial of service (DDoS)
DDoSNamed in the outline and in the threat list as "Denial of Distributed attack (DoS)". No explanatory slide has extractable text. Check the printed slides.2, 41
Application layer
Application layer vulnerabilityListed in the outline only. No content slides have extractable text. Check the printed slides.2
Password attacks
Password crackingRecovering or guessing a password to get into an account or encrypted data.47
Brute forceTries all combinations. Slow, but works on weak passwords.48
Dictionary attackTries common words and combinations. Faster than brute force.48
Hybrid attackDictionary words with numbers or symbols added, e.g. Password123.48
Rainbow tablePrecomputed hash tables. Works when passwords are not properly salted.48
Credential stuffingUses stolen username and password pairs on other platforms, exploiting reuse.48
Firewalls (defence, read before IDS/IPS)
FirewallAn integrated set of measures that blocks unauthorised electronic access. Like fire walls in buildings that isolate compartments.50
Firewall policyPredefined rules that filter incoming and outgoing traffic.51
Policy actionsAccepted (let through). Dropped (blocked silently). Rejected (blocked, and the source is told).52
Policy inputsDecisions use protocol, source and destination IP address and port, and application payload (e.g. a virus).52
Design goalsAll traffic passes through; only authorised traffic is allowed; the firewall is immune to penetration.53
Firewall techniquesService control, direction control, user control, behaviour control.54
Packet filter (stateless)Checks each packet's IP address, port and protocol. Layer 3. Fast and simple, but cannot track sessions. Low security.56
Stateful inspectionTracks active connections and decides in context. Medium security. Layers 3/4. More secure than packet filter.57, 60
Application-level gateway (proxy)Intermediary between user and server. Filters on application data (layer 7). High security, slower.58, 60
Circuit-level gatewayChecks the TCP handshake and verifies sessions. Does not inspect data content. Hides internal hosts.59
Next-generation firewall (NGFW)Traditional firewall plus IPS, deep packet inspection, application awareness and malware detection. Very high security, moderate speed.60
Intrusion detection and prevention (IDS / IPS)
IDSA device, often a separate computer, that monitors for malicious or suspicious events. A sensor that raises an alarm, like a smoke detector.62
IDS responseAlert a human team, or isolate a suspected intruder and restrict access.62
IDS functionsEight functions, e.g. monitoring activity, auditing configuration, recognising known attack patterns. No single IDS does them all.63
HIDSHost-based IDS. Protects one host and its data.64
NIDSNetwork-based IDS. A separate appliance that monitors traffic across a whole network or critical servers.64
IPSIntrusion prevention system. An IDS with a built-in response. Blocks or stops harm, e.g. cuts off a user or rejects an address.65
Signature-based detectionMatches known attack patterns. Needs frequent updates.66
Anomaly-based detectionFlags unusual behaviour. Can find unknown threats.66
Behaviour-based detectionMonitors patterns of system behaviour.66

2. Pre-empted misconceptions

Looks-like pair or wrong beliefThe difference / correctionSlide no
DoS vs DDoSDoS is one attacker against availability. The deck's DDoS slide has no extractable text, so use the DoS definition and check the printed DDoS slide.43, 41
Interception vs interruptionInterception reads or copies data (confidentiality loss). Interruption stops authorised access (availability loss, i.e. DoS).5
Replay vs modificationReplay resends a genuine message unchanged. Modification changes the message en route.14, 21
Component failure vs attackComponent failure is irregular and non-malicious, so rarely an attack. Port scanning does no harm itself but often precedes an attack.27, 28
Dropped vs rejectedDropped gives no failure message. Rejected tells the source the packet was refused.52
Packet filter vs stateful firewallPacket filter checks each packet alone and cannot track sessions. Stateful firewall tracks active connections.56, 57
Stateful vs proxy firewallStateful works at layers 3/4 and is fast. Proxy works at layer 7, filters application data, and is slower.57, 58, 60
Circuit-level vs proxy firewallCircuit-level checks the TCP handshake and does not look inside data. Proxy inspects application data.58, 59
Firewall vs IDSFirewall filters traffic by policy and can block it. IDS only monitors and alerts (a sensor), unless it is an IPS.50, 62
IDS vs IPSIDS detects and alerts, out-of-band, and does not block. IPS detects and blocks automatically, inline, and may block legitimate traffic.62, 65, 66
HIDS vs NIDSHIDS protects one host. NIDS watches traffic across a whole network.64
Signature vs anomaly detectionSignature matches known patterns and needs updates. Anomaly flags unusual behaviour and can catch unknown threats.66
WPA vs WPA2WPA uses TKIP (per-packet key change). WPA2 adds AES encryption. Both differ from WEP's static key.38, 39
