Making and listing: ls, mkdir, rmdir, touch

These four commands list, create and remove the things in a folder, and they cover Lab 1 Questions 1 and 2.

Lesson 2 made folders with mkdir. touch does the same job for an empty file.

The four commands

TypeResult
lsNames in this folder
ls -lOne line of details per item (lesson 4 reads it)
ls *.txtOnly names ending in .txt
mkdir testCreates the folder test
rmdir testRemoves it, only if it is empty
touch a.txt b.txtCreates empty files, one per argument

The * is a wildcard: the shell treats it as "any characters" and swaps *.txt for the matching names before ls runs. The . in *.txt is just the dot in the filename. It has nothing to do with the .. in lesson 2, which is a folder name of its own.

Becoming root

Lab 1 says to run sudo su before the questions. Root is the administrator account, which can read and change anything. sudo su switches your shell to root, and the prompt usually changes from $ to #. Type exit to go back. Do not confuse this with the root directory /: same word, different thing.

The lab questions, run in order

$ sudo su
#
# cd /home/student
# mkdir ahhock
# cd ahhock
# pwd
/home/student/ahhock
# touch a.txt b.txt
# ls
a.txt  b.txt
Critical Exam Trap • rmdir Needs an Empty Folder

The handout shows the error Directory not empty. Empty the folder first, because rmdir never deletes contents.

Correct (earns marks)Incorrect (loses marks)
rm test/a.txt then rmdir testrmdir test (with files inside)

Which command lists only files ending in .pdf?

Yes. * stands for the rest of the name.
Without *, the shell looks for a file literally named .pdf, and a leading - would be read as options.

Reveal the answer

cd ali
