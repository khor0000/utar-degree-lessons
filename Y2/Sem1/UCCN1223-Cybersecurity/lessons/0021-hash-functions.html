Hash functions: a fixed-length fingerprint of any data

A cryptographic hash function turns data of any size into a fixed-length value, called the hash value or digest, and the same data always gives the same digest.

Why this matters: a hash lets a system check data without keeping a copy of it. Signatures sign a digest, and a login compares digests. Focus on: the three properties on slides 50 and 51, and what a digest looks like. Skip for now: the history of the SHA family and MD4/MD5, HMAC, and the random generator for salt. How you'll be tested: the multiple-choice checks here. Not confirmed for the exam; Lab 2 Section 3 uses hashing.

Lessons 8 and 9 showed a cipher as a recipe you can run backwards. A hash is a recipe you cannot run backwards, and that one difference drives everything below.

Looks like encryption (lessons 8 and 9), but it is not. Same: data goes in, a mathematical recipe scrambles it, and the output looks random. Different: encryption has a key and a decryption step, so the owner can get the data back. A hash has no key and no reverse step, so nobody can get the data back from the digest, not even the sender. Why: a hash is meant to be a fingerprint, not a locked box.
Looks like a hash table (UCCD1024), but it is not. Same: the input becomes a number. Different: a hash table uses the number as an array index, and two inputs landing in the same slot (a collision) is normal and gets handled. A cryptographic hash gives a 256-bit value that is not a slot, and finding two inputs with the same value must be infeasible (slide 51). Why: a table only needs quick lookup. A fingerprint must be trusted when an attacker is trying to forge a match.
Looks like the salt in lesson 24, but it is not the same step. Same: a password and a stored value. Different: lesson 24 adds a random salt per user, and the stored value is the hash of password plus salt. A hash alone lets an attacker hash a list of common passwords once and match it against every stolen entry. Slide 58 says salt is "random data added before hashing", which is what breaks that list.

2. The general rule

Slide 46 defines it: a hash function is a mathematical program that takes variable-length data and produces a fixed-length value. Two terms, each with the three parts:

  • Hash function: what it is, a fixed mathematical program. What value it holds, none; it only takes the input and returns the output. Why needed: one short value can stand in for data of any size.
  • Hash value (digest): what it is, the output of the program. What value it holds, a fixed-length string of bits, shown here as 64 hex characters. Why needed: two short values can be compared instead of two large files.

3. The three properties

The deck lists three properties (slides 50 and 51). Each one has a reason:

  • Fixed length (property 1): input of any size gives the same digest length.
  • One-way (property 2): the digest is easy to compute, but very hard to turn back into the data.
  • Collision-free (property 3): a collision is two different inputs with the same digest. It must be very hard to find one.

The deck uses the hash for three things: file integrity (slide 47, compare a digest before and after a download), digital signatures (slide 44, sign the digest of a long message, not the whole message), and password storage (slide 49, the login hashes the typed password and compares it with the stored hash). Database indexing is also named on slide 47; that is the hash-table use from the look-alike box above.

Why one-way and collision-free are two separate properties

One-way asks whether the data can be recovered from the digest. Collision-free asks whether two different inputs can share a digest. A hash can be one-way and still have collisions that are easy to find. Then an attacker can forge a matching input without ever recovering the original.

Check yourself

Which property means you cannot get a file back from its hash value?

Yes. One-way means the data cannot be recovered from the digest.
One-way is the property that blocks recovery. Fixed length and collision-free are the other two, and there is no decryption step in a hash.

What is the output of a hash function called?

Yes. The output is the hash value, also called the digest.
A hash has no key and no ciphertext. Its output is the hash value, also called the digest.

A website stores each user's password as a hash. An attacker takes the stored list and recovers an original password from one hash, without guessing. Which property failed?

Yes. Recovering the data from the hash means the one-way property failed.
Recovering the password from its hash is a failure of the one-way property. The other properties are not about recovery.
