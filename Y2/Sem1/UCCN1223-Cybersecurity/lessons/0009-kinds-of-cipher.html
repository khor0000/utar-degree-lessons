The two kinds of cipher

Ciphers are sorted two ways: by how they scramble (replacing letters or shuffling them) and by how many keys they use (one shared key, or a matched pair).

Lesson 8 showed the five elements of a cryptosystem, using one example: moving each letter 3 places forward, which is the Caesar cipher covered in full in lesson 11. This lesson sorts ciphers by how they scramble, and by how many keys they use.

1. Two ways to scramble: replace, or shuffle

Looks like lesson 8's CYBER SECURITY example, but…
Substitution (the 8 recipe)Transposition (rail fence)
SameBoth change the message with a recipe, and both can be undone by running that recipe backwards
DifferentEach letter becomes a different letter, so the letters themselves changeEach letter stays the same letter and only moves, so the letters stay the same
WhyCount the letters before and after. The same letters in a new order means transposition. A letter swapped for another means substitution

The rule for each one, and how to tell them apart:

Substitution: replace each letterTransposition: shuffle the order
Example with HELLOKHOOR: each letter swapped for another (slide 12)HLOEL: the same letters in a new order (rail fence, slide 12)
What stays the sameThe order of the lettersThe letters themselves
Topic 3a ciphersCaesar, the keyword family, Playfair, HillColumnar transposition
WeaknessThe double L in HELLO becomes a double O, so patterns show throughEvery original letter is still there to count
You might reasonably wonder: if reordering letters scrambles them, is any rearranging encryption? No. Reversing HELLO to OLLEH rearranges the letters, but no secret is involved, so anyone who knows the rule can undo it. Encryption means the scrambling runs with a secret key, so only a key holder can reverse it.

Slide 15 gives the names for what each one achieves: substitution gives confusion, so you cannot tell which letter became which, and transposition gives diffusion, which spreads the message over the ciphertext.

2. One shared key, or a pair of keys

Looks like the password in the ssh login (lesson 7), but…
PasswordSymmetric key
SameBoth are secret, and both must stay away from an eavesdropper
DifferentThe server checks it: does what you typed match the stored one?The scrambling uses it: the same key must be held by both people to read the message
WhyA password is only compared with a stored record. A symmetric key is put into the recipe itself, so it changes the output
You might reasonably wonder: if the two keys are different, how can one open what the other locked? Because they are a matched pair: each undoes the other.
SymmetricAsymmetric
KeysOne key, shared by both peopleTwo different keys: a public one and a private one
Everyday pictureA house key: you hand a copy to anyone who needs to get inA parcel locker: anyone can drop a parcel in, but only the person with the pickup code can open it
Advantage (slide 9)Gives authenticity, as long as the key stays secretExcels at key management
Problem (slides 9 and 50)Key distribution: the shared key has to reach the other person safelyCovered in Topic 3b

Check yourself

HELLO becomes HLOEL. Which kind of cipher made this change?

Yes. H, E, L, L and O are all still there. Only the order changed.
Count the letters: H, E, L, L, O all appear in HLOEL. No letter was replaced, so it is transposition.

In asymmetric encryption, what is the relation between the two keys?

Yes. One key locks and the other unlocks. They are not copies, and only one of them is public.
The two keys are a matched pair, but they are different, not copies. Two public keys, or one key used twice, would not protect the message.
