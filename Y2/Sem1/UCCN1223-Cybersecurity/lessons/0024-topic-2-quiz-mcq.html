Topic 2 quiz check: files, links and passwords

Topic 2 for the quiz is four ideas: a file system is a tree of folders, a hard link is a second name for the same data, a dictionary attack is beaten by salt, and octal codes give permissions. This lesson skips the permission drills, which Lesson 0004 to 0006 already cover.

Hard link vs symbolic link

Hard linkSymbolic (soft) link
The differencePoints to the same inode as the originalCreates its own new inode
Why both matterKeeps the data alive after one name is deletedCan link across file systems and to folders
When to use whichSlide 22 says a hard link cannot cross file systemsSlide 22 says a symbolic link can cross file systems

The four ideas

IdeaWhat to remember (Topic 2, slides 11, 15, 16, 20, 22)
InodeThe record the system keeps for each file: size, owner, permissions and disk location. It does not store the name.
HashA fixed-length fingerprint of data. It cannot be reversed to get the data back.
File system treeFolders hold files and subfolders. The topmost folder is the root.
Hard linkPoints to the original inode. Deleting the original leaves the link holding the data.
Dictionary attackHash each word, compare with stored hashes. Slide 15 says a 500,000-word dictionary is "often enough" to find most passwords.
SaltA random number per user ID, stored with the hash. It makes a precomputed dictionary useless.

Check yourself

What is the topmost folder of a file system tree called?

Yes. The topmost folder is the root folder.
The topmost folder is the root. An inode is metadata about one file, and salt belongs to passwords.

You create a hard link to a file, then delete the original. What happens to the hard link?

Yes. A hard link points to the same inode, so the data stays while any link remains.
A hard link points to the same inode as the original, so deleting the original name does not remove the data.

Which link type creates a new inode?

Yes. Slide 22: a symbolic link creates a new inode, while a hard link does not.
Slide 22 says a symbolic link creates a new inode. A hard link does not.

Why is salt used for passwords?

Yes. Each user has a random salt, so the same word gives a different hash for each user.
Salt is a random value stored with each user ID. It makes the same dictionary of hashes useless against each user.

What does octal 640 mean for a file?

Yes. Slide 35: 640 is read/write for the owner, read-only for the group, and forbidden to others.
Read the digits one by one: owner 6 (rw-), group 4 (r--), others 0 (---). Slide 35 gives that meaning.
