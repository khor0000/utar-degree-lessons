The shell and the shape of a command

The shell is the program that reads the line you type and runs the command it names.

Looks like the Command Prompt or a C++ cin loop: it waits, reads a line, acts, then waits again. The difference is that each line starts a separate program.

What the shell is

The shell is an ordinary program. It (1) is a text-based interface, (2) holds a current folder and a history of commands, and (3) exists so you can control the machine with no mouse. The window it runs in is the terminal. Your Lab 1 sheet uses the two words loosely, and for this lab that causes no harm.

The prompt is the text the shell prints when it is ready. In the handout it is $. You never type the $; when the sheet shows $ pwd, you type pwd and press Enter.

Every line has the same shape

The spaces matter: the shell uses them to split the line into pieces. The piece -l starts with -, which by convention marks an option. Here -l asks ls for the long listing. The piece /home is the argument, and lesson 2 explains its /.

You might reasonably wonder: must every command have all the parts? No. Only the command is required, so plain ls is valid.

Critical Exam Trap • The Space Before the Option

The shell splits on spaces, so a missing space makes one unknown command name.

Correct (earns marks)Incorrect (loses marks)
ls -lls-l

In mkdir test, which piece is the argument?

Yes. mkdir is the program, and test is what it works on.
The command comes first. The argument follows it.
Paper task

Label each piece of chmod 750 test.txt as command or argument. You do not need to know what it does yet.

Reveal the answer

chmod is the command. 750 and test.txt are both arguments, because neither starts with -.
