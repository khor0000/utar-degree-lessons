The designer's model and the user's model

The designer's conceptual model reaches the user only through the system image, the screens, behaviour and documentation. The user builds a mental model from that, so the two pictures can differ.

Lesson 14a defined the conceptual model as the designer's plan. This lesson shows how that plan reaches the user.

Looks like the conceptual model, because both name the same things. It differs in whose picture it is. The conceptual model lives in the designer's diagrams. The mental model lives in the user's head.

Stage 1, the designer's plan. The conceptual model lives in the designer's hands and the team's diagrams. No user has seen it yet.

Stage 2, the system image. Users never see the plan. They see only the screens, what the system does, and any manual. The designer can steer the user's picture only through this.

Stage 3, the mental model. The user builds their own picture from the system image. It can differ from the plan, because no single designer's plan fully reaches the user (Benyon ch2, PDF p60).

Two pictures compared

Conceptual modelMental model
Whose pictureThe designer'sThe user's
How it formsWritten down by the designer, before the system is builtBuilt by the user, by using the system and reading its documentation (Benyon ch2, PDF p60)
How it behavesA stated plan, which the team can discuss and reviseIncomplete, unstable and not always scientific (Benyon ch2, PDF p61)

You might reasonably wonder whether the two should match. The book wants the designer's model communicated so clearly that people quickly develop a clear mental model (Benyon ch3, 3.2, PDF p79). That is a goal, not a guarantee. The system image is the only link between the two.

Produce it • closed book • Tutorial 2 Q4

Close lessons 14 to 14b. Answer Q4 on paper: How is conceptual design different from physical design in UX? Then, for a canteen app, define a conceptual model, name one object, one attribute and one relationship with its 1 or m labels, and say how it differs from a mental model.

reveal model answer

Conceptual design is abstract: it concerns the information content and functions a system needs to achieve its purpose, and what someone must know to use it, without deciding how they are distributed. Physical design makes it concrete: it structures interactions into logical sequences, allocates functions between people and devices, and fixes the look and feel through colours, shapes and sizes. Conceptual design answers what the system is for, while physical design answers how it works and looks. For the canteen app, a conceptual model is the designer's abstract description of objects, attributes and relationships. The object is Order, the attribute is pickup time, and the relationship is that a Student places many Orders (1 to m). It differs from a mental model in whose picture it is: the conceptual model is the designer's plan, and the mental model is the user's belief, built from the system image, which can be incomplete or unstable.
