Four activities, one loop

The UX design process has four activities: understanding, design, envisionment and evaluation. Evaluation sits at the centre, and the team goes round these activities in repeated rounds, refining the design each time.

A process is easy to picture as steps done once from top to bottom. This one is not that. The lecture says the process "can start at any stage" (Lecture 2, PDF p4), and the book calls UX design an iterative process, not a linear one (Benyon ch3, 3.1, PDF p77). Lessons 11a to 11f take the four activities and the loop one piece at a time.

Why this matters. Every later lesson sits in one of these four activities. Knowing which one you are in tells you what to do next.

Focus on. The four names, what each one is for, and why evaluation is at the centre.

Skip for now. The Double Diamond and IDEO models (Benyon Figure 3.1). They draw the same process in other shapes.

Looks like Lesson 9's cycle, which is also a loop, but it differs. Lesson 9's loop is a change in the world: new technology changes activities. This loop is the designer's own work on one system.

The loop

Figure 3.2 in the book (PDF p78) puts evaluation in the middle, with the other three activities around it. Each arrow goes both ways, so any activity can feed evaluation, and evaluation can send the team back to any activity. Step through one example: a campus food-ordering app, taken round the loop twice.

Round 1, understanding. Students queue at the canteen, and some have no cash. The activity produces a need and a requirement: order and pay from a phone in under a minute.

Round 1, design. The team shapes the requirement into a conceptual design (menu, order, pay, pick-up time) and a physical design (a large Pay button).

Round 1, envisionment. A clickable prototype of the order screens, so students can react to something real.

Round 1, evaluation. Three students try the prototype. Two miss the Pay button, and one cannot find how to go back. These findings feed the next round.

Round 2, design. The team moves Pay to the bottom of the screen and adds a Back arrow. The physical design changes; the need does not.

Round 2, envisionment. The prototype is rebuilt with the two fixes.

Round 2, evaluation. Five students try it, and all of them pay. They then ask when their food will be ready. That is a new need.

Round 2, back to understanding. The new need goes back to understanding, as an order-status requirement. The loop goes on.

The four activities in one line each

  • Understanding: finding out what the system must do, what it has to be like, and how it fits with other things (Benyon ch3, 3.2, PDF p78). Lesson 11a.
  • Design: creating ideas, then shaping them into a conceptual design (what the system is for) and a physical design (how it works and looks) (Benyon ch3, 3.2, PDF p79). Lesson 11b.
  • Envisionment: making design ideas visible, such as a sketch or a prototype, so the designer and the users can react to them (Benyon ch3, 3.2, PDF p82). Lesson 11b.
  • Evaluation: checking the design with people, at every step of the process (Benyon ch3, 3.2, PDF p78). Lesson 11c.

The next lesson takes understanding in detail, because it is the activity that everything else depends on.

Which statement about the four UX design activities is correct?

Right. Evaluation runs throughout, and the activities can be entered in any order.
Not quite. The process is not a fixed sequence: evaluation runs at every step, and you can start at any activity.
