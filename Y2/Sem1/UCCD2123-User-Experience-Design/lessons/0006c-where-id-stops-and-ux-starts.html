Where ID stops and UX starts

Interaction design decides what the person does, what the system does and in what order, inside an interaction. UX design checks that all the touchpoints fit together and feel consistent. The book does not draw the line as cleanly as the slides do.

Lesson 6b split a journey into touchpoints. This lesson asks which field owns each decision, using the same pay screen.

Looks like the slide's split: ID is one screen, UX is the whole journey. That picture is useful, but the book goes further, as the next section shows.

What ID means

Benyon defines interaction design as the allocation of functions to the person or to the technology, and the structuring and sequencing of the interactions (ch3, 3.2). Plainly: ID decides what the person does, what the phone does, and in what order.

The book's wider view

Chapter 4 (section 4.2) places the moments of interaction inside a bigger picture that it also calls interaction design: the whole user journey. So the book files the whole journey under interaction design as well. The slides' split, ID for one interaction and UX for the whole, is a working emphasis, not a wall between two fields.

The test (working rule, not in the book): if the fix reorders steps or changes what the system does, it is an ID decision. If it adds or changes a touchpoint, or makes touchpoints match each other, it is a UX design decision. Use the test to decide which decision you are describing, and expect the two fields to overlap at the journey level.

Two products do not automatically mean two ID jobs. Count the interactions that need designing.

The pay screen asks for PIN before showing the amount; designers swap the order. Which is it?

Right. Reordering steps inside the pay screen is ID.
Not quite. Reordering steps inside one interaction is ID, not a new touchpoint or a study.

Stalls add an 'e-wallet accepted' sign and owners get a payment sound. Which is it?

Right. A new sign and a sound are new touchpoints, and UX design shapes them as one set.
Not quite. Adding a sign and a sound adds touchpoints across the journey, which is UX design.
Run it • fresh input

For Grab food delivery, name three touchpoints, one ID decision at one of them, and one UX design decision across them.

reveal model answer

Three touchpoints: the order screen in the app, the push notification that says the rider is on the way, and the in-app chat with the rider.

ID decision (order screen): the app shows the total before it asks for the payment PIN or biometric, so the customer sees what they are paying first. This reorders steps, so it is ID.

UX design decision (across them): the order screen, the notification and the chat all use the same status words ("on the way", "arrived") and the same tone, so the customer reads one consistent story over time.
