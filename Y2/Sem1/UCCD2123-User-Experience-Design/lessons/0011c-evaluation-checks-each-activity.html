Lesson 11c · Tutorial 2 Q1

Evaluation checks each activity, with no fixed next step

Every activity is followed by an evaluation, but the book does not say what comes after that evaluation. So there is no fixed chain such as understanding, evaluation, design, evaluation, and so on.

Lesson 11 put evaluation at the centre of the loop. This lesson answers the question that follows: if evaluation comes after each activity, what decides the next step?

Looks like a checklist you tick after every step, but it differs. The check is not always a test with users. It can be the designer rereading their own work.

Every activity hands its output to evaluation

The book's rule is that any of the other design activities will be followed by an evaluation (Benyon ch3, 3.2, PDF p83). So an evaluation attaches to each activity: to a list of requirements, to a sketch, and to a prototype.

The check can be light. The book says it can be simply the designer checking that work is complete and correct. It can also be a list of requirements sent to a client, or a formal test with users (PDF p83). Evaluation is not only a formal test.

The next step is not fixed

You might reasonably read the rule as a fixed chain: understanding, evaluation, design, evaluation, envisionment, evaluation. The book's own example is one path among many. Understanding might be evaluated, then a prototype built and evaluated, and then some physical design identified (Benyon ch3, 3.2, PDF p78). The word "might" marks an example, not an order.
