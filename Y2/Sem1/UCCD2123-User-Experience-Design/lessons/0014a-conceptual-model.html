Conceptual model: objects and relationships, no screens

A conceptual model is the designer's abstract description of the main objects in a system, their attributes, and how they relate. It names no screen, button or device.

Lesson 14 said conceptual design stays abstract. This lesson shows what a conceptual model holds, using the canteen meal from Lesson 14.

Looks like the mental model in Lesson 14, because both name the same things. It differs in whose picture it is. The conceptual model is the designer's written plan. The mental model is a user's belief, built by using the app. Lesson 14b covers that difference.

What it is

Conceptual model: a description of the main objects in a system, their attributes, and the relationships between them. Benyon ch3, 3.6, PDF p97

It is a diagram or list that the designer writes, not software that runs. It holds three kinds of content:

  • An object is a thing the system deals with, such as an order.
  • An attribute is a fact that describes one object, such as the pickup time of an order.
  • A relationship links two objects. It says how many of one can link to how many of the other, written as 1 for one and m for many. This labelling is standard diagram notation; the book describes the same idea in words.

What one looks like

Draw only the objects and how they relate. Step through it.

Stage 1, objects and attributes. Five things the system deals with. Each attribute is a fact about one object, such as the pickup time on an order.

Stage 2, relationships. A student places many orders, and each order has one student. Many orders are for one stall. Each order is settled by one payment. The 1 and m say how many, not which ones.

Stage 3, check the abstraction. Nothing here names a screen, a button, a device or a QR code. The same model would still be true if the canteen used a phone app, a web page or a counter kiosk.

The abstraction test

The book says conceptual design focuses on the what rather than the how (Benyon ch3, Box 3.2, PDF p81). So the model says what the system must know and do. It is not the app; physical design decides which screens and devices realise it.

Working rule (not in the book): if one screen or device could be swapped for another without making the model false, the model is still abstract.

Which statement about a conceptual model is correct?

Right. A conceptual model is the designer's abstract description of objects, attributes and relationships. The user's picture is the mental model.
Not quite. The picture a user forms is the mental model. A conceptual model is the designer's abstract description of objects, attributes and relationships, with no screens or colours.

A diagram shows that a student places many orders and each order is for one stall. Why is it still conceptual?

Right. Abstraction is what makes it conceptual. The drawing style does not decide it, and the checking does not turn a plan into a belief.
Not quite. Being drawn does not make a model conceptual, and a screen description is physical. What decides it is that the model names objects and relationships, and nothing about how they are shown.
